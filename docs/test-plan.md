# План тестирования CaRider, версия 0.2 (UC-01)

## 1. Объект тестирования

Сценарий UC-01 «Заказ поездки и поиск таксиста»: шаги 1–6, исключения 4а и 5а, альтернатива 3а и отмена заказа. Модули accounts, orders и dispatch; версия — состояние ветки main на начало недели 12 (`git log -1 --oneline`).

## 2. Что тестируем

- Бизнес-правила: БП-01 (поиск таксиста до 15 с), БП-02 (клиент подтверждает цену, которую видел), БП-05 (бесплатная отмена в течение 1 минуты).
- Технологическое требование Т-5: один таксист не может выполнять два заказа одновременно.
- Исключения: 4а (нет связи при расчёте цены), 5а («Свободных машин нет»), предусловие UC-01 (клиент не найден или заблокирован).
- Формат ввода: пункт назначения (до 250 символов), телефон (+7 и 10 цифр), цена (целое число больше нуля), тело запроса (JSON-объект).
- Переходы состояний заказа: создан, назначен, отменён и запрещённые переходы.
- Коды ответов API по контракту ЛР №6, все 5 операций.
- Экраны Э-01…Э-05 и их особые состояния.

## 3. Что не тестируем и почему

- Вход по SMS, оплата, БП-03, БП-04, БП-06 — ещё не реализованы в этой итерации.
- Нагрузка (1000 одновременных заказов, НФТ-04) и безопасность — вне рамок учебной итерации. Одновременные запросы проверены только ограничением СУБД, без параллельного запуска.
- Мобильное приложение Flutter — его ещё нет; админ-панель — служебный код.

## 4. Уровни и методы

| Уровень | Метод | Инструмент |
| --- | --- | --- |
| Модульный | Чёрный ящик: классы эквивалентности, границы, таблица решений, переходы состояний | unittest, заглушка часов |
| Модульный | Белый ящик: граф потока, покрытие ветвей | coverage.py --branch |
| Интеграционный | Сверху вниз: представление с заглушкой слоя логики | unittest.mock |
| Системный | Ручные тест-кейсы, кросс-тестирование | браузер, GitHub Issues |

## 5. Среда

Windows, Python 3.13, Flask 3.1, SQLite, Chrome. Данные — фикстура demo.json (`flask --app carider loaddata demo`).

## 6. Критерии входа

Проект запускается по README (migrate, loaddata, run), 39 тестов ЛР №7 проходят, установлен пакет coverage.

## 7. Критерии окончания

- все автоматические тесты проходят, `ruff check .` — без ошибок;
- покрытие ветвей слоя логики (services.py) не ниже 90 %;
- каждая строка таблицы трассировки ЛР №7 и каждая строка таблиц тест-дизайна проверена хотя бы одним тестом;
- нет открытых дефектов серьёзности «Критическая» и «Высокая»;
- все Issues кросс-тестирования разобраны: исправлены, отклонены с объяснением или помечены later.
