# Журнал дефектов

Д-1…Д-3 воспроизведены намеренно на коде ЛР №7: вносилась одна правка, запускались тесты, по сообщению об ошибке находилась строка, правка отменялась коммитом `fix:`. Д-4…Д-8 найдены тестами «чёрного ящика» в ЛР №8 на настоящем коде.

| № | Симптом | Тип | Как найдена | Причина и исправление | Коммит |
| --- | --- | --- | --- | --- | --- |
| Д-1 | «Свободных машин нет» появляется не на 15-й секунде, а позже (нарушена граница БП-01) | Логическая | Упали 3 теста, в том числе `test_no_drivers_boundary_at_15_seconds`: `AssertionError: NoDriversError not raised`. В отладчике на строке `if now - started ...` значение `now - started` равно `0:00:15`, как и `SEARCH_TIMEOUT` | В `dispatch/services.py` стояло `>` вместо `>=`: ровно 15 секунд не считались таймаутом. Заменено на `>=` | `fix: граница таймаута поиска включительна (>=)` |
| Д-2 | Экран Э-03 падает с ошибкой 500, когда свободных машин нет | Времени выполнения | Трассировка в тесте `test_search_without_explicit_now_compares_aware_datetimes`: `TypeError: can't subtract offset-naive and offset-aware datetimes` в `find_driver` | `now_utc()` вернула время без часового пояса, а время заказа хранится с UTC; их нельзя вычитать. Возвращено `datetime.now(UTC)` | `fix: часовой пояс UTC у текущего времени` |
| Д-3 | Страница Э-03 не открывается | Синтаксическая | Тест `test_no_drivers_screen_and_cancel`: `jinja2.exceptions.TemplateSyntaxError: Encountered unknown tag 'endblock' ... currently looking for 'endif'` | В шаблоне `search.html` пропущен `{% endif %}`. Тег возвращён | `fix: закрыт тег if в шаблоне поиска` |
| Д-4 | Телефон `+77010000001` с переводом строки на конце или с арабскими цифрами проходит проверку формата, API отвечает 401 вместо 400 | Логическая | Класс эквивалентности «недопустимый формат телефона», `test_invalid_phones_are_400`: `AssertionError: 401 != 400` | В `forms.py` выражение `^\+7\d{10}$` с `re.match`: `$` допускает перевод строки на конце, а `\d` принимает цифры любых алфавитов. Заменено на `re.fullmatch(r"\+7[0-9]{10}")` | `fix: телефон — строгий формат (fullmatch, цифры 0–9)` |
| Д-5 | Запрос с `"destination": null` или числом даёт 404 «Такой адрес не нашли» вместо 400 | Логическая | Класс «адрес не строка», `test_missing_or_null_destination_is_400` и `test_destination_in_order_must_be_a_string`: `AssertionError: 404 != 400` | `str(None)` превращал `null` в строку «None», и она искалась как адрес. Не-строка теперь считается пустой (`_text()` в `forms.py`, проверка `isinstance` в `views.py`) | `fix: пункт назначения должен быть строкой` |
| Д-6 | Цена `1850.5` принимается, заказ создаётся (201), хотя цена — целое число | Логическая | Класс «дробное число», `test_price_must_be_a_positive_integer`: `AssertionError: 201 != 400` | `int(1850.5)` молча отбрасывает дробную часть. Числа с плавающей точкой и `true`/`false` отвергаются до `int()` | `fix: цена — только целое число` |
| Д-7 | Страница «Заказ отменён» открывается у заказа, который никто не отменял, и пишет «Штраф не взят» | Логическая | Переходы состояний, `test_screen_is_not_available_for_active_order`: `AssertionError: 200 != 409` | `cancelled_screen()` не проверял статус заказа. Для неотменённого заказа теперь `OrderStateError` (409) | `fix: экран отмены только для отменённого заказа` |
| Д-8 | `POST /api/quotes/` с телом-массивом `[1, 2]` или строкой падает с ошибкой 500 | Времени выполнения | Класс «тело — не JSON-объект», `test_body_must_be_a_json_object`: `AttributeError: 'list' object has no attribute 'get'` | `or {}` спасал только пустое тело: непустой массив считался данными. Если тело не словарь, оно считается пустым, API отвечает 400 | `fix: тело запроса должно быть JSON-объектом` |
