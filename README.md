# CaRider — заказ такси через мобильное приложение

Габбасов Алимжан · группа 25-16 · проект CaRider (ЛР №1–7)

Серверная часть и первая рабочая версия основного сценария UC-01: клиент вводит адрес, видит цену и условия, подтверждает заказ, система находит ближайшего свободного таксиста (шаги 1–6), клиент может отменить заказ. Мобильное приложение Flutter подключится к этому API позже; сейчас экраны Э-01…Э-05 показаны веб-страницами сервера. Вход по SMS в этой версии не реализован: клиента определяет номер телефона (демо-клиент +77010000001).

## Стек

Python 3.12, Flask 3.1, SQLite (при разработке; в эксплуатации — PostgreSQL 16), клиент — Flutter 3.
Обоснование — [ADR-001](docs/adr/ADR-001-stack.md), слой данных — [ADR-002](docs/adr/ADR-002-data-layer.md).

## Как запустить

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
flask --app carider migrate
flask --app carider loaddata demo
flask --app carider run
```

(macOS и Linux: `source .venv/bin/activate` вместо второй строки.)

- `migrate` создаёт таблицы, `loaddata demo` загружает демонстрационных клиентов, таксистов и адреса. Без этих двух команд будет ошибка `no such table`.
- Открыть http://127.0.0.1:5000/ — экран Э-01. Введите «ул. Ауэзова, 42», нажмите «Рассчитать стоимость», отметьте согласие и нажмите «Заказать»: появится экран «Водитель найден».
- Админ-панель: http://127.0.0.1:5000/admin/ (логин `admin`, пароль `admin`; в эксплуатации задайте переменную `CARIDER_ADMIN_PASSWORD`).
- Остановить сервер — Ctrl+C.

## API

| Операция | Метод и адрес |
| --- | --- |
| Рассчитать стоимость | `POST /api/quotes/` |
| Подтвердить заказ | `POST /api/orders/` |
| Результат поиска таксиста | `GET /api/orders/{id}/driver/` |
| Повторить поиск | `POST /api/orders/{id}/search/` |
| Отменить заказ | `POST /api/orders/{id}/cancel/` |

Ошибки возвращаются как `{"error": {"code": "...", "message": "..."}}`.

## Структура

- `carider/` — серверное приложение
  - `accounts/` — клиенты и таксисты
  - `orders/` — заказы: расчёт цены, создание, отмена (Э-01, Э-02, Э-05; БП-02, БП-05)
  - `dispatch/` — подбор водителя (Э-03, Э-04; БП-01)
  - в каждом модуле: `models.py` (данные), `repository.py` (SQL), `services.py` (правила), `views.py` (экраны и API), `errors.py` (исключения UC-01)
  - `migrations/` — SQL-миграции, `fixtures/demo.json` — демонстрационные данные
  - `db.py` — подключение и миграции, `events.py` — события между модулями, `admin.py` — админ-панель
- `tests/` — автоматические тесты
- `docs/` — ADR и журнал дефектов `defects.md`

## Соглашения о коде

| Правило | Как в CaRider |
| --- | --- |
| Стиль | PEP 8; форматирование — `ruff format`, длина строки 88; клиент на Dart — `dart format` |
| Имена | Функции и переменные — snake_case, классы — PascalCase, константы — UPPER_CASE; имена в коде на английском |
| Комментарии | На русском; у каждой публичной функции и класса — строка документации, у правила — ссылка на БП-xx |
| Слои | `views.py` вызывает только `services.py`, `services.py` — только `repository.py` и сервисы других модулей; бизнес-правила БП-xx — только в `services.py` |
| Модули | Один пакет на модуль; зависимости только по таблице модулей, без циклов; `orders` не импортирует `dispatch`, связь — событие `order_created` |
| Исключения | Исход сценария — класс-наследник `CariderError` с `http_status` и `message`; `except Exception` не используется |
| База данных | Структуру меняют только новой миграцией; файлы `*.sqlite3` не коммитят |
| Проверка перед коммитом | `ruff check .` — 0 ошибок, `python -m unittest` — OK |
| Коммиты | Conventional Commits: feat, fix, docs, test, refactor, chore; одно изменение — один коммит |
| Секреты | Пароли и ключи — только в переменных окружения или `.env` (файл в `.gitignore`) |
